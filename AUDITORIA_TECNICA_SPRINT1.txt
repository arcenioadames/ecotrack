Evaluación de arquitectura:

Separación de responsabilidades: BIEN
Detalle: Controller -> Service -> Prisma limpiamente separado

Modularidad: BIEN
Detalle: Validators, utils, config en carpetas propias

Reusabilidad: REGULAR
Detalle: JWT + middleware reusable, pero patrones no generalizados

Escalabilidad: REGULAR
Detalle: Estructura funciona para 1-2 features, pero para 10+ se necesita abstracción

DRY (No Repetición): REGULAR
Detalle: Error handling repetido en controllers

Testing: BIEN
Detalle: Mockeable (Prisma, bcrypt, JWT)

Deuda técnica de arquitectura:

1. Sin base service: Cada service repite la misma lógica de error handling
2. Sin repository pattern: Prisma acoplado directamente a servicios
3. Sin dto/mapper: No hay transformación input -> domain -> output
4. Sin use cases: Lógica de negocio vive en servicios, sin separación de casos
5. Sin middlewares transversales: Logging, error handling centralizado falta

Recomendación para Sprint 2: Introducir Repository pattern + AppException + Middleware centralizado.

POST /auth/login
- Ruta: backend/src/routes/auth.routes.ts

- Validador: backend/src/validators/auth.validator.ts
- Tests: backend/tests/unit/services/auth.service.test.ts

POST /auth/refresh
- Ruta: backend/src/routes/auth.routes.ts
- Controller: backend/src/controllers/auth.controller.ts
- Service: backend/src/services/auth.service.ts
- Validador: backend/src/validators/auth.validator.ts
- Tests: backend/tests/unit/services/auth.service.test.ts

GET /health
- Ruta: backend/src/app.ts
- Propósito: Health check
- No requiere autenticación

GET /api-docs
- Ruta: backend/src/app.ts
- Propósito: Swagger documentation
- Archivo config: backend/src/config/swagger.ts

Middleware disponible:

authenticate: backend/src/middlewares/auth.middleware.ts
- Verifica JWT en header Authorization: Bearer <token>
- Valida firma y expiración
- Agrega req.user con {sub, role}

authorize(...roles: Role[]): backend/src/middlewares/auth.middleware.ts
- Verifica que req.user tenga uno de los roles especificados
- Devuelve 403 Forbidden si no cumple

Variables de entorno requeridas:

DATABASE_URL: Connection string con PgBouncer
DIRECT_URL: Connection directa para migraciones
ACCESS_TOKEN_SECRET: Secret para JWT access tokens
REFRESH_TOKEN_SECRET: Secret para JWT refresh tokens
BCRYPT_SALT_ROUNDS: Rounds para bcrypt (recomendado 12)
POLICY_VERSION: Version actual de politicas
CORS_ORIGIN: Origins permitidos para CORS
PORT: Puerto del servidor (default 3000)
NODE_ENV: Entorno (development, test, production)
